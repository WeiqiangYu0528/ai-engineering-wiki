## Overview
**Synthetic Data** is data generated by models (or rule engines) to supplement human-curated corpora for pretraining, fine-tuning, and evaluation. The DeepMind-led survey (arXiv 2404.07503) frames the core lesson: generation is easy, but ensuring **quality, factuality, fidelity, unbiasedness, trustworthiness, and privacy** is hard — and quality dominates model gains per scaling-law intuition. The DAIR Applications guides show three production prompting patterns that make generation practical: vanilla count-constrained synthesis, intent-specific PROMPTGATOR distillation for retrievers, and randomized-entity diversity seeding for pretraining (TinyStories/Phi-1). CS336 Lectures 14–16 [[source-cs336-lecture14-data-filtering]] [[source-cs336-lecture15-sft-rlhf]] [[source-cs336-lecture16-rlvr]] extend this to modern LLM-driven pipelines — **OpenThoughts 1.2M (QwQ-32B), SWE-smith/ZERO/rebench 50K–12M agentic coding tasks, Nemotron-CC rephrasing/QA, and Qwen 3 midtraining** — where synthetic data now scales pretraining, SFT, and RLVR.

## Key Ideas
- **Quality bottleneck:** "The more high-quality data we give these models, the better the performance. Creating synthetic data is not hard but ensuring its quality is really the challenge."
- **Evaluation checklist:** Six axes recur — quality, factuality, fidelity (distribution match to real data), unbiasedness, trustworthiness, privacy. Failures on any axis (e.g., hallucinated facts, amplified bias) propagate into downstream models.
- **Lifecycle coverage:** Applications span pretraining mix-ins, instruction-tuning demonstrations, preference data, and evaluation suites; each demands distinct handling of leakage and skew.
- **Related work hub:** The survey's bibliography is highlighted as a primary reading list for the field.
- **Pattern 1 — Vanilla counts ([[source-promptingguide-applications-generating]]):** `Produce 10 exemplars for sentiment analysis … Produce 2 negative and 8 positive … Use Q: <sentence> A: <sentiment>` — shows prompt numeric constraints control class balance and format; useful for rapid eval bootstrapping but high-temp alone does not ensure diversity at scale.
- **Pattern 2 — PROMPTGATOR retriever distillation ([[source-promptingguide-applications-synthetic-rag]]; Dai et al. 2022):** With only 8 few-shot `(doc, query)` pairs + intent prompt `Task: Identify a counter-argument… Argument #1: {X1} → query {Y1} … Argument N: {long passage} → query:`, generate synthetic `(query, doc)` pairs for each unlabeled document. Formal: $(e_{prompt}, e_{doc}(d_1), e_{query}(q_1), …, e_{doc}(d))$ → 50k synthetic ≈ 10k manual labels; cost 50k docs × (700 input + 25 output) ≈ $55 via GPT-3.5; intent sensitivity (ArguAna counter-argument vs support) must be encoded; random sampling from ~20 exemplars boosts diversity; best for niche/low-resource domains (Czech laws, Indian tax assistant) where generic retrievers fail.
- **Pattern 3 — Diversity seeding & hierarchical generation ([[source-promptingguide-applications-generating-textbooks]]; Eldan 2023 TinyStories, Gunasekar 2023 Textbooks Are All You Need / Phi-1):** Naïve high temperature yields repetitive corpora. Fix: pre-build vocabularies (1500 basic words → nouns/verbs/adjectives) + feature lists (dialogue, plot twist, bad ending, moral) and inject random entity per prompt:
  `Write a short story (3-5 paragraphs) which only uses very simple words that a 3 year old child would likely understand. The story should use the verb "{verb}", the noun "{noun}" and the adjective "{adj}". Features: {feat1, feat2}…` — produces divergent stories even with overlapping words. Hierarchical variant generates intermediate summary/required sentence before final story. Workflow: Identify variable entities → compile collections → random-sample + temp > default but < max → train local model; label can be injected as entity. Phi-1 applies `topic` (Singular matrices) + `target audience` (1st-year bachelor / high-schooler / PhD phrasing) to generate 1B textbook tokens (overview → natural-language solution → ≤10-line Python snippets) via GPT-3.5; 1.3B Phi-1 rivals 10× larger on HumanEval. Cost ≈ $2000 prompt + $2000 generation.
- **Pattern 4 — Verifiable & agentic generation for midtraining/post-training (CS336 L14–L16):** Modern pipelines replace heuristic diversity with **environment-grounded task construction**:
  - *OpenThoughts* (L14): 27 sources (StackExchange, NuminaMath, Chemistry) → 1.2M examples via QwQ-32B teacher, 16 responses/prompt helps, better model ≠ better teacher (QwQ-32B > R1 as teacher), answer filtering didn't help [[source-cs336-lecture14-data-filtering]].
  - *SWE family* (L14): SWE-smith (LM-introduced bugs → 50K/128 repos), SWE-Zero (300K agent trajectories without execution via internal world model — strong models solve many tasks without exec — plus 150K PRs with OpenHands scaffold removing future commits to block git-hacking; 12M scale with mini-coder 1.7B pass@100=50.4), SWE-rebench (21K interactive / 3.4K repos via Qwen 2.5-72B installer/rater, 450K PRs).
  - *Nemotron-CC* (L13): for low-quality CC, LM rephrasing; for HQ, LM-generated QA/key-info extraction — 6.3T with HQ 1.1T [[source-cs336-lecture13-data-sources]].
  - *Qwen 3 midtraining* (L16): joint text+code CC via LLM HTML parsing, 600B repo-level concat + PRs with RAG context, LM-prompted QA on coding docs, agent trajectories — plus expert web/UX/QA/SWE distillation (800K auto-built SWE envs) [[source-cs336-lecture16-rlvr]].
  - *Reasoning SFT traces* (L15–16): Alpaca 52K (Davinci-003) → ShareGPT 168K → distilled R1 800K long-CoTs for Qwen distillation (distilled Qwen > RL-from-scratch on small bases) and 1K cold-start for GRPO [[source-cs336-lecture15-sft-rlhf]] [[source-cs336-lecture16-rlvr]].

## How It Works
Typical pipeline: prompt a capable model to generate tasks/rationales/labels → filter/re-rank with verifiers (factuality checks, fidelity metrics, bias audits) → mix with real data → train. Unfiltered synthetic data risks mode collapse and hallucination amplification. CS336 adds environment-grounded loop: define envs (repos, Docker) → define tasks/prompts (real PRs vs LM-bugs) → collect teacher responses (QwQ-32B, Qwen3-Coder-480B, Gemini) → filter via execution or LM-judge.

**Prompt-driven variants:**
```
Vanilla:        count + format constraint → 10 sentiment Q:A
PROMPTGATOR:    [intent instruction + 2-8 (doc,query) few-shots] + new doc → new query (last pair kept)
Diversity-seeded: random entities/topic×audience per prompt (+ hierarchical summary/sentence) → story/textbook extract
Verifiable:     env + difficulty filter (best-of-8 failures) → teacher traces → verifier (unit tests / is_equivalent) → RL (GRPO)
Agentic:        repo state + PR context (RAG) → agent scaffold (OpenHands/mini-swe) → trajectory (+ optional exec) → filtered SFT/RL
```
All rely on [[in-context-learning]] instruction following; quality still hinges on exemplar representativeness and filtering (DeepMind checklist + CS336 difficulty filtering: exclude MC/T-F false positives, keep best-of-8 failures, remove too-similar-to-val, manual guess-vs-correct audit per Kimi/Qwen 3 [[source-cs336-lecture16-rlvr]]).

## Practical Implications
- **Data-centric leverage:** At fixed compute, investing in synthetic-data filtering often outperforms scaling parameters — ties to [[scaling-laws]] data frontier. Qwen 3's 3,995-example GRPO beating larger runs and Phi-1's 1.3B > 10× larger are exemplars [[source-cs336-lecture14-data-filtering]] [[source-cs336-lecture16-rlvr]].
- **Risk coupling:** Without factuality verification, synthetic data bakes [[hallucination]] into weights; without bias audits, it entrenches [[llm-bias]]. Gekhman 2024 note per L15: synthetic SFT on unknown facts teaches wrong extraction [[source-cs336-lecture15-sft-rlhf]].
- **Production need:** Standardized synthetic-data eval (fidelity scores, leakage tests) should precede any large-scale mix-in. CS336 tip: sample multiple responses/prompt (16× helps) but answer filtering often doesn't; prioritize diverse sources over sheer scale (small HQ > large diverse per OpenThoughts) [[source-cs336-lecture14-data-filtering]].
- **Pattern selection:** Use vanilla for quick eval sets; PROMPTGATOR for retriever domains with available unlabeled corpus but <10k labels; diversity-seeded for pretraining/mid-scale where repetition is fatal — combine with [[chain-of-thought]] for reasoning-heavy corpora; **verifiable** for math/code RL (unit tests/`is_equivalent` boxed check + 800K math equivalence RM per Kimi) and **agentic** for SWE (execution vs no-execution world-model trajectories) [[source-cs336-lecture16-rlvr]].
- **Cost rule-of-thumb:** 50k synthetic retriever pairs ≈ $55 (GPT-3.5) vs >$1000 manual; 1B textbook tokens ≈ $4000 prompt+gen — validate prompt ROI before scaling. Code envs dominate: SWE-Zero 800K tasks need Docker scaffolding + git-hacking guard (remove future commits); budget infra before generation.
- **Teacher quality nuance:** Better model ≠ better teacher (QwQ-32B > R1 for OpenThoughts) — choose teacher for distillation transfer, not raw benchmark [[source-cs336-lecture14-data-filtering]]; similarly, R1 800K distilled Qwen beats RL-from-scratch at small scale [[source-cs336-lecture16-rlvr]].

## Connections
- Feeds [[pretraining]] and [[supervised-fine-tuning]] corpora; interacts with [[chinchilla]] token/param frontier and [[alignment]] preference data; midtraining (Qwen 600B repo-level) is the bridge between [[pretraining]] and [[rlhf]].
- Complements [[retrieval-augmented-generation]]: synthetic data improves parametric memory, while RAG supplements non-parametric memory.
- Evaluated via faithfulness ideas adapted to training data; RLVR verifiers extend to training signal (accuracy reward).
- Realized in [[applications-overview]] alongside [[code-generation]] and [[prompt-function]]; agentic SWE trajectories are the coding instantiation.
- Contrasts [[retrieval-augmented-generation]] grounding: synthetic queries can hallucinate → needs retriever verification loop.
- Orchestrated by [[data-curation]] filtering/mixing and consumed by [[reasoning-llms]]/[[thinking-models]] via distillation and GRPO.

## Open Questions
- What automated fact-checking harness reliably certifies synthetic-data factuality at scale without human-in-the-loop? Kimi's 800K equivalence RM is a start but math-specific.
- How to measure and enforce distributional fidelity without leaking private training samples?
- At what synthetic-to-real ratio does diversity seeding saturate vs degrade (mode collapse) for pretraining? Nemotron-CC rephrasing already spans low→high quality with different synthetic ops — saturation unknown.
- When can no-execution SWE-Zero (internal world-model) replace execution-dependent trajectories — how to detect world-model failure without running? [[source-cs336-lecture14-data-filtering]]
- Does LM-judge filtering (V3 as judge for 600K reasoning SFT in R1) introduce reward-model bias that GRPO later amplifies? [[source-cs336-lecture16-rlvr]]
